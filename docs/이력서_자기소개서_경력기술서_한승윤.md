# 2. 자기소개서 (Cover Letter)

### 고난을 지나 더 나아진 나로

2024년 봄 대학 복학 직후 마주한 강의실은 내게 큰 전환점이었습니다. 강의실에서 마주한 생성형 AI는 기존에 많은 시간을 들여 작성하던 코드를 단 몇 초 만에 쏟아내고 있었습니다. 학부 프로젝트는 교수님의 평가표 점수만 맞추는 일회성 타이핑에 불과했고, 실제 배포나 운영 경험이 없던 탓에 코딩 문법을 파는 일에 깊은 회의감이 들었습니다. 비슷한 시기, 오랜 기간 디자인 일을 하던 사촌 형이 AI의 영향으로 업계를 떠나 도축업으로 이직했다는 소식까지 겹치며 "이러다 AI에게 밀려 밥벌이나 할 수 있을까"라는 불안이 엄습했습니다. 결국 학업을 손에서 놓고 부사관 입대를 진지하게 고민하며 진로를 원점에서 재검토하는 시간을 가졌습니다.

전환점은 3학년 겨울방학, 동시접속 20명 규모 게임 커뮤니티의 수작업 온보딩 비효율을 직접 자동화해 보기로 결심하며 찾아왔습니다. `rpg_sync_project`를 설계하여 미국 GCP 무료 단일 노드(1GB RAM)에 직접 배포하고 실운영에 들어갔습니다. 로컬에선 에러가 없던 코드가 한국 DB와의 200ms 네트워크 지연과 커넥션 풀 고갈, 메모리 부족으로 뻗는 것을 보며, 시스템을 살려내는 일은 프롬프트가 아닌 인프라 통제에 있음을 몸으로 부딪치며 배웠습니다. 소켓 상태 검사와 50MB 상한의 Redis 캐시 계층을 구현해 무중단 운영을 지켜내던 중, 해당 게임 서버의 실이용자였던 현직 개발자와 커피챗을 진행했습니다. "실제 서비스 운영 경험 자체는 긍정적이나, 정량적인 스펙을 보강하고 부트캠프를 통해 완성도 높은 프로젝트를 여러 개 진행하며 운영 경험의 폭을 더 넓혀보라"는 현실적인 피드백을 받았습니다.

현직자의 조언을 즉시 행동으로 옮겨 학교 수업 대신 부트캠프를 택했고, 4인 팀의 조장으로서 프로젝트 협업 환경을 구축했습니다. AI 코드를 맹신하지 않고 셸과 파이썬 코드로 통제하던 원칙을 팀 CI 파이프라인에 적용해 디렉터리 격리 하드가드를 설계했습니다. 그러나 2026년 9월 30일, 시나리오 1을 마친 직후 돌아보니 각자의 작업 공간을 지나치게 나눈 하드가드 때문에 오히려 모듈 간 데이터 정합성이 깨져버리는 위기가 터졌습니다. 저녁 마무리 리추얼에 '강점 행동: 못 했다'고 적으며 "진짜 좀 쉬자"고 한숨을 남겼을 만큼 지친 날이었지만, 도망치지 않았습니다. 나는 쉬어가려던 계획을 즉시 접고 팀원들과 긴급 회의를 열어 문제를 공유했습니다. 불변 데이터 계약을 재정의하고 하네스 규칙을 선제적으로 개편하여 정합성을 정상 복구했습니다. 팀원들로부터 "예상치 못한 위기에서도 동요하지 않고 팀을 이끈다"는 신뢰를 얻은 전환점이었습니다.

방황과 실전 운영, 그리고 협업의 위기를 통과한 지금의 나는 2026년 10월 14일 아침 일기에 스스로 다짐하듯 적었던 그대로, "내 에이전트를 맹신하지 않고 항상 계측 데이터와 증거를 요구하는 사람"이 되었습니다. 13주 동안 매일 아침 출결 루틴을 지키고 50일간 리추얼을 빠짐없이 기록하며 회복탄력성을 숫자로 증명했습니다. 단순히 돌아가는 코드를 짜는 것을 넘어, 어디서 어떻게 터질지 실패 지점을 먼저 의심하고 선언적 자동화로 시스템의 가용성과 무결성을 지키는 클라우드 인프라 엔지니어로 나아가고 있습니다.
